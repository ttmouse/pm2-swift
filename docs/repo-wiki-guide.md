# Qoder REPO WIKI 功能指南

## 概述

REPO WIKI 是 Qoder 的智能项目文档生成功能。它能**自动分析代码仓库的结构、架构和依赖关系**，生成结构化的项目知识库（Wiki），并持续跟踪代码变更进行增量更新。

---

## 一、REPO WIKI 是什么

REPO WIKI 的核心价值在于 **将隐性的代码知识转化为显性的结构化文档**。它解决的痛点：

| 痛点 | REPO WIKI 如何解决 |
|------|-------------------|
| 新成员看不懂项目结构 | 自动生成架构图、模块说明 |
| 文档滞后于代码 | 持续跟踪 Git 变更自动更新 |
| 遗留系统无文档 | 深度解析旧代码，弥补文档缺失 |
| 团队知识分散 | Wiki 可共享、编辑、导出 |

### 在 Qoder Harness 体系中的位置

REPO WIKI 是 Qoder **Harness Engineering** 方法论四要素之一：

| 要素 | 说明 |
|------|------|
| **Rules（规则）** | 架构、编码、测试、工作流硬性规则 |
| **Skills（技能）** | 可复用的开发流程 |
| **Wiki（知识库）** | 分层上下文（Always/Phase/On-demand） |
| **Changes（变更追溯）** | 变更记录与 Audit Trail |

## 二、点击"生成"时——完整执行流程

当用户在 Qoder 界面侧边栏点击 Wiki 按钮或"生成"按钮时，以下流程在后台依次执行：

### 阶段 1：代码扫描与结构分析

```
用户点击"生成"
      │
      ▼
┌─────────────────────────────────────┐
│ 1. 仓库扫描                          │
│    ├── 识别语言/框架/技术栈            │
│    ├── 解析目录结构                   │
│    └── 识别构建系统/依赖管理文件        │
└─────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────┐
│ 2. 依赖关系映射                      │
│    ├── 模块间引用分析                 │
│    ├── 数据流追踪                     │
│    └── 外部依赖识别                   │
└─────────────────────────────────────┘
```

**具体执行内容**：

1. **文件系统遍历** — 递归扫描仓库内所有源文件
2. **技术栈识别** — 分析 `package.json`、`Podfile`、`go.mod`、`*.xcworkspace` 等标识文件
3. **目录结构建图** — 构建文件树和模块边界
4. **依赖拓扑分析** — 跨文件引用追踪，构建依赖有向图
5. **入口点定位** — 识别 main 函数、App 入口、路由注册点

### 阶段 2：架构理解与知识提取

```
┌─────────────────────────────────────┐
│ 3. 架构模式识别                      │
│    ├── 识别 MVVM/MVC/Clean 等模式     │
│    ├── 标注分层边界（View/Service等） │
│    └── 识别设计模式使用               │
└─────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────┐
│ 4. 知识提取                          │
│    ├── 模块职责摘要                   │
│    ├── 关键类/函数说明                │
│    ├── 数据模型定义                   │
│    ├── API 端点映射                  │
│    └── 业务流程梳理                   │
└─────────────────────────────────────┘
```

**具体执行内容**：

1. **架构模式匹配** — 通过代码组织方式推断架构模式（如 View/ViewModel/Model 目录 → MVVM）
2. **模块职责归纳** — 分析每个目录/文件的导入依赖和导出符号，归纳其职责
3. **关键符号提取** — 识别 public/open 类、协议定义、主要函数签名
4. **数据流分析** — 追踪核心数据流向（用户操作 → Controller → Service → Database）
5. **UML 生成** — 自动绘制组件图、时序图、类图、流程图

### 阶段 3：文档生成与组织

```
┌─────────────────────────────────────┐
│ 5. Wiki 目录创建                     │
│    └── 在仓库中创建结构化文档目录      │
└─────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────┐
│ 6. 分层文档生成                      │
│    ├── 项目概览（README 风格）        │
│    ├── 架构文档（模块/分层/依赖）      │
│    ├── API 文档（接口/数据模型）       │
│    ├── 数据库文档（ER 图/模型定义）    │
│    └── 部署文档（环境/构建/运行）      │
└─────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────┐
│ 7. AI 上下文注入                     │
│    └── 文档纳入 Qoder 上下文系统       │
└─────────────────────────────────────┘
```

**具体执行内容**：

1. **Wiki 目录创建** — 在仓库创建 `.qoder/wiki/` 或指定的 Wiki 目录
2. **文档模板填充** — 使用识别到的项目信息填充预定义文档模板
3. **可视化嵌入** — 插入自动生成的 UML 图表和架构示意图
4. **索引构建** — 生成可搜索的索引文件，便于 AI 快速定位
5. **上下文注册** — 将生成的文档注册到 Qoder 的分层上下文系统

### 阶段 4：增量维护与持续同步

```
Git 提交/分支切换
      │
      ▼
┌─────────────────────────────────────┐
│ 8. 变更检测                          │
│    ├── 对比 Git HEAD 差异            │
│    ├── 标记受影响模块                 │
│    └── 评估文档滞后程度               │
└─────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────┐
│ 9. 增量更新                          │
│    ├── 仅更新受影响文档片段           │
│    ├── 智能合并（保留手动修改）        │
│    └── 冲突标记                      │
└─────────────────────────────────────┘
```

**具体执行内容**：

1. **Git 钩子监听** — 感知 commit、branch switch 等事件
2. **差异增量分析** — 只分析变更部分，不重新扫描全量代码
3. **智能合并** — 自动更新自动生成的内容，保留用户手动修改的部分
4. **滞后告警** — 检测到文档与代码不一致时主动提示刷新

## 四、生成产出的具体内容

REPO WIKI 在项目中生成的内容包括：

### 文档产出

| 文档 | 内容 |
|------|------|
| **项目概览** | 技术栈、目录结构、快速开始 |
| **架构文档** | 分层架构图、模块依赖图、数据流图 |
| **API 文档** | 端点列表、请求/响应格式、认证方式 |
| **数据库文档** | ER 图、表结构、索引、关系 |
| **部署文档** | 环境要求、构建步骤、运行配置 |
| **组件文档** | 核心类/函数说明、设计模式使用 |

### 可视化产出

- **组件图** (Component Diagram) — 展示系统高层模块及依赖
- **时序图** (Sequence Diagram) — 展示关键业务流程交互
- **类图** (Class Diagram) — 展示核心数据模型关系
- **流程图** (Flow Chart) — 展示业务流程
- **ER 图** (Entity-Relationship) — 展示数据模型

### AI 上下文产出

- **AGENTS.md** — 分层上下文（Always Loaded / Phase-triggered / On-demand）
- **CONTEXT.md** — 领域上下文：核心概念、业务规则、术语表
- **规则目录** — `.qoder/rules/` 架构/编码/测试/工作流规则

## 五、关键特性

### 全自动同步

- **首次生成**：全量扫描分析
- **增量更新**：Git HEAD 变更时自动触发，仅处理变更部分
- **智能合并**：自动内容可覆盖，手动修改保留

### 高效低耗

- **认知体系预构建** — 首次分析后建立知识索引
- **增量而非全量** — 后续变更开销极小
- **本地执行** — 代码不出本地，安全可控

### 规模限制

| 指标 | 限制 |
|------|------|
| 单工程文件上限 | ~6000 个文件 |
| 四千文件处理时长 | ~2 小时（全量） |
| 增量更新 | 秒级到分钟级 |

### 协作支持

- **共享** — Wiki 可推送到远程仓库供团队使用
- **编辑** — 支持手动修改和补充
- **导出** — 可导出为独立文档

## 六、使用场景

### 1. 新项目启动

创建新项目后一键生成 Wiki，快速输出：
- 架构图和模块说明
- 接口手册
- 快速开始指南

面对无文档的老项目，REPO WIKI 自动：
- 深度解析旧代码逻辑
- 弥补文档缺失
- 理清模块间依赖关系

新成员加入时：
- 快速理解代码库全貌
- 减少口头讲解成本
- 提升上手效率

### 4. AI 辅助开发

为 AI Agent 提供精准上下文：
- 准确回答技术问题
- 精确定位相关代码
- 辅助新功能开发和缺陷修复

## 八、FAQ

**Q: REPO WIKI 会修改我的代码吗？**
A: 不会。它只读取代码进行分析，在独立目录生成文档文件。

**Q: 生成的 Wiki 文档可以手动修改吗？**
A: 可以。手动修改的内容在增量更新时会被保留，Qoder 采用智能合并策略。

**Q: 生成需要多长时间？**
A: 取决于仓库大小。小型项目（几十个文件）几分钟，大型项目（数千文件）可能需要数小时。

**Q: Wiki 可以分享给团队成员吗？**
A: 可以。Wiki 文档存储在仓库中，推送到远程后团队成员均可访问，也支持导出。

**Q: 代码修改后 Wiki 会自动更新吗？**
A: 是的。Git HEAD 变更时自动触发增量更新，但首次生成需手动点击"生成"。

**Q: 支持哪些编程语言和框架？**
A: 支持主流编程语言（Swift、JavaScript/TypeScript、Python、Java、Go、Rust、Ruby 等）和框架（SwiftUI、React、Vue、Spring Boot、Django 等）。
